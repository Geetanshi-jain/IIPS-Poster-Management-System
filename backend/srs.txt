## 3. Project objective

The application manages the complete lifecycle of academic poster competitions at IIPS, DAVV.

An authorized administrator creates and publishes an event. Eligible students browse events, register when required, and submit research posters. Administrators assign reviewers. Reviewers independently evaluate assigned posters using an event-specific rubric. The system calculates final scores, produces event-specific rankings, provides analytics and allows authorized publication of results.

Each poster must belong to exactly one event. Scores, evaluation criteria, reports and rankings must remain associated with the correct event.

The application must support multiple events simultaneously.

## 6. Core business rules

Implement these rules in the backend, not just in the UI.

1. Only admins can create or publish events.

2. Only published events can accept submissions.

3. Registration, eligibility, allowed domains and deadlines must be checked on the server.

4. Each poster belongs to one event.

5. Every poster submission must have a valid submitter and an authorized set of authors.

6. Each poster can be assigned to multiple reviewers.

7. Each reviewer can review multiple posters.

8. Reviewers cannot evaluate unassigned posters or their own work.

9. Each reviewer submits an independent evaluation.

10. Each submitted evaluation must include valid marks for all required rubric criteria.

11. Evaluation scores must be calculated server-side. Ignore any client-supplied final score.

12. A final score must only be generated when the event's required reviews are complete.

13. Use the mean of valid completed reviewer scores by default, unless the event has an explicitly configured alternative.

14. Define tie handling consistently, such as equal ranks for equal final scores. Use additional tie-breaking rules only if approved and documented.

15. Rankings must always be scoped to one event.

16. Do not mix posters from different events.

17. Unpublished results must not be exposed to students.

18. Submitted evaluations must be immutable to reviewers unless an authorized reopening process exists.

19. Any administrative override must be authorized and audited.

20. Prevent duplicate submissions or registrations where the configured rules disallow them.

Clearly distinguish poster acceptance status from score and rank. A poster can have a completed score without necessarily being accepted, depending on the event rules.
